# Journal の検証

2026年10月12日、日本時間での追加実装を対象にしています。正式なストア記事・画像を取得できなかったため、実際の Liquid テンプレートと Broadcast の既存 CSS・JavaScript に、明記したローカル記事・告知・写真枠・Instagram URL を接続して検証しました。画像枠は服や商品の代替画像ではありません。

`browser-validation.json` は PC 1440px とスマホ390pxを含む30ケースです。公開日順の新着、手動記事選択、下書き・未来公開の除外、長い日本語タイトル、写真のない記事、正しい既存記事URLへのリンクを確認しました。既存の記事 DOM が変わらず、新しい全CSSを適用しても元の記事の文字・色・幅・余白が変わらないことも確認しています。

60件の告知を使い、Shopify の paginate に相当するローカル adapter で1ページ目と6ページ目を確認しました。同じ記事への複数更新、対象記事からのタイトル・写真・URL取得、任意の上書き、対象不明の非表示、読みものブログをお知らせとして誤用しない保護も確認しています。

ライブは開催予定・配信中・終了・延期・中止を手動状態で確認しました。予定時刻の経過で配信中にならず、期限なし・期限切れでは配信中バッジを出しません。開いたままの期限切れ、表示期間の終了、履歴の保持、アーカイブ未登録時の非表示、次回予定の日時順、編集時の再接続を確認しました。日本時間の変換はJavaScriptに頼らず、UTC日付跨ぎ・年跨ぎ・うるう日でも確認しています。

Instagram は登録したプロフィール・投稿URLを参照し、不正なホストや未設定項目を表示しません。スマホで1写真が十分な幅を持ち、3写真の横スクロールがページ全体の横はみ出しを起こさないこと、キーボードのフォーカス、動きを減らす設定、JavaScript無効時の表示を確認しました。

`offline-preview-validation.json` は単一HTMLのPC・スマホ2ケースです。最初のローカルHTTP読み込み後にネットワークを全遮断し、ホームとJournalの移動、記事・外部リンクの制限案内、閉じた後のフォーカス復帰を確認しました。直接 `file://` で開く操作は未確認です。

`capture-validation.json` と `capture-contact-sheet.png` は12枚の画像の検証です。撮影だけは即時スクロールを使い、対象の位置と表示画像の読み込みを待っています。全画像の非空白をチェックし、対象の見出し・カード・タイムライン・プロフィール・ライブが写っていることを目視で確認しました。撮影用の調整をテーマの実コードへ加えていません。

実ストアの管理画面での保存、正式な記事本文・公開日・SEOデータ、Shopify側の同期、実配信、正式Instagramアカウント、iOS実機では未確認です。テーマコードから既存記事を書き換える処理はありません。ローカル記事データは納品するテーマファイルへ含めません。
