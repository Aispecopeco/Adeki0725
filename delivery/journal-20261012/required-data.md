# TA VIE｜Journal追加機能に必要な情報

既存記事は現在のShopifyデータを参照します。今回の追加表示のために本文・写真・タイトルを複製する必要はありません。未確認の更新履歴、ライブ予定、Instagramアカウントは初期データとして作成していません。

## 公開までに設定する項目

| 対象 | 必要な情報・作業 | 設定場所 |
| --- | --- | --- |
| 既存のJournal記事 | 現在の掲載ブログを確認して選択 | テーマ設定 `tvj_blog` |
| Journal LP | 新しい紹介用ページ、`journal` テンプレートの割り当て、そのページの選択 | ページ管理、テーマ設定 `tvj_page` |
| おすすめ記事 | 掲載したい既存の公開済み記事を1本選択。未選択でも最新記事を候補にできます。 | テーマ設定 `tvj_featured`、またはJournalセクション |
| お知らせ | Journalとは別の専用ブログを作成・選択 | ブログ管理、テーマ設定 `tvj_updates_blog` |
| お知らせ・ライブの入力欄 | `ta_vie_notice` 名前空間のブログ記事メタフィールド定義 | 設定 → カスタムデータ → ブログ記事 |
| Instagram | 実際のプロフィールURLと表示するアカウント名 | テーマ設定のInstagram共通項目 |
| ナビゲーション | 追加フッター入口のリンク確認。必要に応じてヘッダーメニューへJournalページを追加 | テーマエディタ、メニュー管理 |

具体的な型・キー・画面・登録手順は [setup-guide.md](setup-guide.md) に記載しています。

## 写真と文章

| 素材 | 使用箇所 | 用意する内容 |
| --- | --- | --- |
| 既存記事のアイキャッチ | ホームのカード・Journalのおすすめ・一覧 | 元の記事に登録済みの写真を使用。追加用に同じ写真を再登録しません。 |
| 既存記事の概要 | 各記事紹介 | 元の記事の概要を優先。概要が空の場合は既存本文から短く抜粋します。紹介文を整えるときは元の記事の概要欄を編集できます。 |
| Instagram紹介写真 | ホーム／JournalのInstagram案内 | 実際の着用、素材の接写、ブランドの日常など。権利のある写真を選択します。 |
| Instagram投稿写真・URL | 最大3件の投稿紹介 | 写真と実際の投稿URLをセットで登録。投稿内容と合う写真を使用します。 |
| ライブ告知写真 | ライブ案内・タイムライン | 実際の配信内容を伝える写真。未設定でもテキスト主体で表示できます。 |
| 記事更新の短い説明 | タイムライン | 何を追加・修正したか、運営者が告知したい内容だけを入力します。 |
| Instagram紹介文 | フォロー導線 | 何を見られるかを短く説明します。未実施の活動や投稿内容を断定しません。 |
| 定期開催の案内 | ライブ案内 | 運営上確定している曜日・頻度だけ設定。未確定なら空欄にします。 |

画像がない記事は写真のないカードとして成立します。写真のない枠を架空の実物写真で埋めたり、ダミー画像を公開したりしません。Instagramの有効なリンクが未設定の場合は、無効なフォローボタンを表示しません。

## ライブごとに必要な情報

- 告知のタイトル、短い説明、任意の写真。
- 開催日時と、日本時間での確認。
- 状態：開催予定／配信中／終了／延期／中止。
- 実際のInstagram告知・視聴先URL。
- 任意の紹介商品と、関連記事の参照ハンドル。
- 必要に応じた告知の表示開始・終了日時。
- 配信中の有効期限。開始時刻を過ぎただけで配信中にはしません。
- 終了後、実際に公開されたアーカイブURLがある場合だけ登録。

これらは **専用のお知らせブログ内の1つの告知記事** にまとめ、共通設定 `tvj_live_articles` でその記事を選択します。最大12件を選択できます。同じ回のライブをホーム用・Journal用として別々に作成する必要はありません。

共通選択が空の場合のライブ候補は、専用お知らせブログの最新50件です。古い告知記事も案内したい場合は共通選択へ登録します。タイムラインの過去履歴はJournal LP内のページ送り、またはお知らせブログ一覧から辿れます。告知の表示期間を過ぎても、公開済みのタイムライン履歴は残ります。

## 今回未取得の実データと、残る確認

公開ストアはパスワードページへ転送され、記事JSONやRSSは401でした。現在の記事数・実際のブログハンドル・記事本文・写真・メニュー項目・公開状態・SEO設定は、この作業環境から取得できませんでした。Instagramの実アカウントも未提供です。

管理画面への認証がないため、ブログ・ページ・メタフィールド定義の作成、実際の記事選択、ライブの登録、Shopify上での保存確認は管理者による設定が残ります。GitHubのテーマコード同期は、これらのストア管理データを自動作成しません。

既存の記事ページ・ブログ一覧のコードを保護した状態で部品を追加していますが、実データを用いた最終確認では、元の記事本文・写真・URL・公開日・レイアウトが維持されていることと、追加したカード・タグ・お知らせリンクの行き先を確認してください。
