# TA VIE｜Journal・お知らせ・Instagram Live の設定と運用

今回の追加機能は、既存のShopifyブログ記事を参照して表示します。記事本文・写真・URL・ハンドル・公開日・SEO設定を移動・複製して構成し直す必要はありません。

ストアは現在パスワード保護され、この作業環境にはShopify管理画面への認証がありません。以下のブログ作成、ページ作成、メタフィールド定義、実際の記事選択・保存はストア管理者が行う設定です。テーマファイルをGitHubへ反映しても、これらの管理データは自動作成されません。

## 1. 既存のブログを選ぶ

Shopify管理画面の「コンテンツ → ブログ記事」を開き、現在の記事を掲載しているブログ名を確認してください。管理画面の版によっては「オンラインストア → ブログ記事」にあります。

「オンラインストア → テーマ → カスタマイズ」を開き、テーマ設定の **「TA VIE｜Journalと発信」** で、Journalの掲載ブログ（`tvj_blog`）にその既存ブログを選びます。名称をJournalへ変更したり、既存記事を別のブログへ移したりする操作は不要です。

おすすめ記事（`tvj_featured`）には既存の公開済み記事を1本選択できます。未選択の場合は、掲載ブログの最新の公開済み記事が候補になります。記事タイトル・写真・公開日・概要・URLは、その記事から読み込みます。

保存後、ホームのカードから既存記事が開くことを確認してください。記事本文は元のページで読みます。未来の公開日時を指定した記事・下書きは公開紹介に使用しません。

## 2. Journalの特集ページを作る

「コンテンツ → ページ」（版によっては「オンラインストア → ページ」）で、以下のページを追加します。

| 項目 | 入力値 |
| --- | --- |
| タイトル | `Journal` |
| 本文 | 空欄で構いません。紹介文はテーマエディタで設定します。 |
| テーマテンプレート | `journal`（ファイルは `templates/page.journal.json`） |
| URLハンドル | `journal` を候補にします。既存の同名ページがある場合は、その用途を確認して別の未使用ハンドルを選びます。 |
| 公開状態 | 公開。公開準備中は非公開のまま設定を確認できます。 |
| 検索エンジン向けのページタイトル・説明 | 実際のTA VIEの紹介として管理者が入力します。 |

テーマ設定のJournalページ（`tvj_page`）で、作成したページを選択して保存します。LP用のページを作成すると、ホームと追加したフッター入口の「Journalを読む」がそのページへ移動します。ページが未設定の間は、選択済みの既存ブログへ移動する仕組みです。

テーマエディタ上部のページ選択から「ページ → journal」を開き、**「TA VIE｜Journal特集」** を編集します。見出し・紹介文・おすすめ記事・記事数・最終更新日表示・タイムライン・Instagram案内の表示を調整できます。このLPだけのおすすめ記事が設定されている場合は、共通設定より優先します。

タグの入口は既存記事のタグから生成し、元のブログのタグ別一覧へ移動します。過去の記事は既存ブログ一覧のページ送りから読めます。今回のLPは元のブログ一覧のURLと表示を保ちます。

## 3. ホームとナビゲーションを確認する

テーマエディタでホームを開き、**「TA VIE｜Journalとご案内」** を確認します。基本は最新の公開済み記事を3本表示します。「表示する記事数」で1〜6本に変更できます。「記事の選び方」を「手動で選択」にすると、「手動で紹介する記事」で最大6本を選べます。選択は記事そのものへの参照なので、ホーム用にタイトルや写真を入力し直す必要はありません。

ホームの「TA VIE｜お知らせタイムライン」で最新の表示件数を変更でき、「TA VIE｜Instagramとライブ」で見出し・余白を調整できます。各追加セクションは独立して非表示にできます。元のBroadcastのブログ・記事テンプレートは変更していません。

フッターには **「TA VIE｜Journalへの入口」** を追加しています。Journalページを選択すると、そのページへ移動する入口が表示されます。ヘッダーにも置きたい場合は、管理画面の「コンテンツ → メニュー」（版によっては「オンラインストア → ナビゲーション」）で `main-menu` を開き、以下を追加します。

| 項目 | 入力値 |
| --- | --- |
| 名前 | `Journal` |
| リンク | 作成済みのJournalページをページ選択から指定 |

既存のメニュー項目を残して保存し、PCヘッダーとスマホメニューの両方でリンクを開いて確認してください。今回のフッター入口は、既存のメニューデータを書き換えずに使えます。

## 4. 専用のお知らせブログを用意する

既存のJournalブログとは別に、**お知らせ用のブログ** を1つ作成します。「コンテンツ → ブログ記事」のブログ管理から以下を登録してください。

| 項目 | 入力値 |
| --- | --- |
| ブログ名 | `TA VIE お知らせ` |
| URLハンドル | `ta-vie-updates` を候補にします。未使用であることを確認してください。 |
| 用途 | 記事公開・記事更新・ブランドのお知らせ・Instagram Live の告知 |

テーマ設定のお知らせブログ（`tvj_updates_blog`）でこのブログを選びます。Journalの掲載ブログと別のブログを選ぶことが前提です。

ここには、運営者が告知したい内容を **1件につき1つの新しい短いお知らせ記事** として追加します。既存のJournal記事を複製する運用ではありません。過去の告知はそのまま残し、同じ記事の次の更新は別の告知として作成できます。

告知記事の公開日時がタイムラインの「掲載日」です。既存Journal記事の公開日と異なる意味を持ちます。告知記事は公開日時順に並び、過去の告知はJournal LPのタイムライン内のページ送り、またはお知らせブログ一覧から確認できます。

## 5. お知らせ記事のメタフィールドを定義する

管理画面の「設定 → カスタムデータ → ブログ記事」（版によっては「設定 → メタフィールドとメタオブジェクト → ブログ記事」）で、次の定義を追加します。

名前空間はすべて **`ta_vie_notice`** です。記事を入力する画面へ固定表示できる定義は固定すると運用しやすくなります。ストアフロントへのアクセス設定がある場合は読み取りを許可します。

| 表示名 | キー | Shopifyの型 | 用途・入力値 |
| --- | --- | --- | --- |
| TA VIE｜お知らせの種別 | `kind` | 1行のテキスト `single_line_text_field` | 選択肢：`publication` 記事公開、`update` 記事更新、`brand` ブランド、`live` Instagram Live |
| TA VIE｜対象の記事 | `target_article` | 1行のテキスト | 既存記事の `ブログハンドル/記事ハンドル`。記事公開・更新では必須。 |
| TA VIE｜表示用タイトル | `display_title` | 1行のテキスト | 任意。空欄なら対象記事のタイトルを使います。対象記事がない告知では告知記事のタイトルを使います。 |
| TA VIE｜表示用写真 | `display_image` | ファイル参照 `file_reference`、画像に限定 | 任意。空欄なら対象記事のアイキャッチを使います。対象記事がない告知では告知記事の写真を使います。 |
| TA VIE｜短い説明・更新内容 | `summary` | 複数行のテキスト `multi_line_text_field` | 更新の場合は、実際に何を変えたかを簡潔に入力。 |
| TA VIE｜告知先リンク | `link` | URL `url` | 任意。対象記事以外の告知先がある場合。 |
| TA VIE｜ライブ状態 | `status` | 1行のテキスト | 選択肢：`planned` 開催予定、`live` 配信中、`ended` 終了、`postponed` 延期、`cancelled` 中止 |
| TA VIE｜ライブ開催日時 | `starts_at` | 日付と時刻 `date_time` | 実際の予定日時。サイトでは日本時間と分かる表示にします。 |
| TA VIE｜告知表示開始 | `show_from` | 日付と時刻 | 任意。ライブ案内を見せ始める日時。 |
| TA VIE｜告知表示終了 | `show_until` | 日付と時刻 | 任意。ライブ案内を見せる期限。 |
| TA VIE｜配信中の有効期限 | `live_until` | 日付と時刻 | `live` のときに設定。配信中表示が残り続けないための期限。 |
| TA VIE｜Instagramの視聴・告知URL | `instagram_url` | URL | 実際の告知投稿・Instagramプロフィールなど。 |
| TA VIE｜公開済みアーカイブURL | `archive_url` | URL | 実際に公開されたアーカイブがある場合だけ入力。 |
| TA VIE｜紹介する商品 | `product` | 商品参照 `product_reference` | 任意。既存の商品を選択。 |

`kind` と `status` は上記の英字値を選択肢として登録してください。定義の管理画面で選択肢の制約を追加できない場合は、表の英字値をそのまま入力します。

対象記事には、例えば実際の記事URLが `https://店舗ドメイン/blogs/room-journal/記事ハンドル` なら **`room-journal/記事ハンドル`** と入力します。これは入力形式の例です。新しい記事ハンドルを作成する意味ではありません。URLの `/blogs/` より後ろの2部分をコピーし、`?` 以降のクエリや `#` 以降の位置指定は除きます。

Shopify公式CLIの現行型一覧に `article_reference` がないため、対象記事には対応する1行テキスト型を使っています。テーマが `articles[handle]` で元の記事を参照し、タイトル・写真・リンクを取得します。記事本文やカード情報の二重入力は不要です。

日時の入力は、管理画面が表示するタイムゾーンを確認してください。ストアのタイムゾーンは「設定 → 一般」で確認できます。連携ツールからISO形式で入力する場合、日本時間は **`YYYY-MM-DDTHH:mm:ss+09:00`** です。保存後、サイトに表示される開催日時と「日本時間」の表示を確認してください。上記表は定義であり、架空の開催日時や告知データを登録する指示ではありません。

定義の入力値は同梱の `metafield-definitions.json` にもまとめています。`python delivery/journal-20261012/setup-metafields.py` はネットワーク通信なしで定義を検査します。管理者が安全な環境変数 `SHOPIFY_STORE` と `SHOPIFY_ADMIN_ACCESS_TOKEN` を設定した環境では、`--plan` で既存定義を確認し、`--apply` で不足する定義だけを追加できます。既存の定義・記事本文・公開状態を変更しません。この作業では認証がないため、ストアへの追加は実行していません。

## 6. Instagramを設定する

テーマ設定の「TA VIE｜Journalと発信」で次を登録します。ホームとJournalが同じ共通設定を使います。

| 設定ID | 入力する内容 |
| --- | --- |
| `tvj_instagram_account` | 実際のTA VIEのアカウント名。表示名として使用。 |
| `tvj_instagram_url` | 実際のInstagramプロフィールURL。 |
| `tvj_instagram_description` | Instagramで何を見られるかを伝える短い紹介文。 |
| `tvj_instagram_image` | 紹介写真。権利のある実際の写真を選択。 |
| `tvj_instagram_button_text` | 例：`Instagramでフォローする` |
| `tvj_recurring_text` | 定期開催が確定している場合の案内文。予定未確定なら空欄。 |
| `tvj_instagram_post_1_image` / `tvj_instagram_post_1_url` | 1件目の紹介写真と、その実際の投稿URL。 |
| `tvj_instagram_post_2_image` / `tvj_instagram_post_2_url` | 2件目。任意。 |
| `tvj_instagram_post_3_image` / `tvj_instagram_post_3_url` | 3件目。任意。 |

写真とリンクを手動で登録する方式です。Instagramからの投稿自動取得・API連携・ログイン・自動埋め込みは不要です。写真を更新したいときは上記の選択写真・投稿URLを変更します。

新しいプロフィールURLが空欄の場合、既存のテーマ設定のInstagram URLが有効なInstagramのリンクであれば利用できます。未設定の状態では架空のアカウント名や無効なフォローボタンを公開しません。Gitの現在設定にはInstagram URLが登録されていないため、管理者による登録が必要です。実際のストア側で設定済みかは、この環境では確認できません。

## 7. 次回ライブを中央管理する

お知らせブログに、1回のライブにつき1つの告知記事を作成します。タイトル・告知写真を登録し、メタフィールドの `kind` を `live` にします。予定日時、説明、状態、視聴URL、紹介商品・関連記事を、その同じ告知記事に設定します。

テーマ設定の **ライブ案内に使う告知記事（`tvj_live_articles`）** で、その告知記事を選択してください。最大12件を共通で選択できます。ホーム・Journalのライブ案内とタイムラインが、同じ告知記事の予定・状態・アーカイブURLを参照します。別の場所へ同じ予定を入力し直す必要はありません。

ライブ記事の共通選択が空の場合は、お知らせブログの最新50件から候補を探します。古くに告知した将来のライブや、50件より前のアーカイブも案内したい場合は、共通選択へ明示的に追加してください。タイムラインの過去履歴自体は、Journal LPのページ送り、またはnativeのお知らせブログ一覧から確認できます。

状態の運用は次のとおりです。

| 状態 | 変更するタイミング |
| --- | --- |
| `planned` | 開催予定を正式に告知したとき。開始予定時刻を過ぎても自動で配信中にはなりません。 |
| `live` | 運営者が実際のInstagram配信開始を確認したとき。`live_until` も設定します。 |
| `postponed` | 延期を決定したとき。説明へ変更内容を書き、新しい日時が決まれば `starts_at` を更新します。 |
| `cancelled` | 中止を決定したとき。理由や案内は確認できる内容だけ入力します。 |
| `ended` | 終了したとき。実際の公開アーカイブがあれば `archive_url` を追加します。 |

告知の表示開始・終了は、ホーム／Journal内の大きなライブ案内の表示期間です。タイムラインの公開済み告知は期間外でも履歴として残します。過去の告知を消す必要はありません。

配信中の有効期限を過ぎると、古い配信中表示を抑制し、「配信状況をご確認ください」と表示します。期限切れだけを根拠に、配信終了やアーカイブ公開を推測することはありません。配信後には運営者が状態を更新してください。アーカイブのURLがない場合は「アーカイブを見る」を出しません。

## 8. 自動で変わる項目と、入力する項目

| 自動で反映される項目 | 管理者が登録・更新する項目 |
| --- | --- |
| 既存記事のタイトル・アイキャッチ・タグ・概要・URL・公開日 | 掲載する既存ブログ、Journalページ、おすすめ記事・手動紹介記事 |
| 公開日時に基づく新着記事の並び | 新規記事の本文・写真・公開状態・公開日時 |
| 設定した場合の、記事の最終更新日表示 | 告知の種別・掲載日時・更新内容・対象記事 |
| 共通の告知記事を参照する各所のライブ日時・状態・アーカイブ | ライブ予定・延期・中止・配信開始確認・終了・期限・実際のアーカイブURL |
| 公開日時に基づくお知らせの並びと、過去一覧へのリンク | Instagramアカウント・写真・プロフィールURL・投稿URL・定期開催案内 |

最終更新日はShopify上の最終保存の日時です。何を変更したかまでは自動で判断しません。古い記事を修正しても、新着一覧の並び基準は元の公開日です。

## 9. 日々の短い運用手順

### 記事を公開する

1. 既存のJournalブログへ記事を追加し、本文・アイキャッチ・概要・タグ・SEOを入力します。
2. 公開状態と公開日時を確認して保存します。
3. ホームの新着カードとJournalの一覧から、実際の記事URLへ移動できることを確認します。

### お知らせを追加する

1. 専用のお知らせブログに新しい短い告知記事を追加します。
2. `kind` を選びます。記事公開・更新は `target_article` に元の記事の参照ハンドルを入力し、更新なら `summary` に変更内容を書きます。
3. 告知の掲載日として公開日時を設定し、公開して保存します。元の記事の公開日は変更しません。
4. タイムラインの種別・掲載日・対象記事リンクを確認します。

### 次回ライブを登録する

1. お知らせブログに1件の告知記事を追加し、`kind=live`、`status=planned`、`starts_at`、説明・写真・実際のInstagram URLを設定します。
2. 告知の表示期間を必要に応じて設定し、告知記事を公開します。
3. 共通設定の `tvj_live_articles` で、その同じ記事を選択して保存します。
4. ホームとJournalの日時が一致すること、Instagramリンクが実際のアカウントへ移動することを確認します。開始時に `live` と有効期限、終了時に `ended` と実在するアーカイブURLを更新します。

## 10. 管理画面で最後に確認すること

- 既存のブログ一覧・記事URLを開き、本文・写真・レイアウトが変わっていないこと。
- ホーム／Journal／タイムラインから正しい公開済み記事へ移動すること。
- Journalページに `journal` テンプレートを割り当て、テーマ設定で実際のページを選択していること。
- Journalとお知らせのブログが別のブログであること。
- PC・スマホで件数、長いタイトル、写真のない記事を確認すること。
- Instagramのプロフィール・投稿・視聴・アーカイブURLが実際の公開先に届くこと。
- ライブの予定・配信中・延期・中止・終了と有効期限を保存し、両ページで確認すること。

実店舗の商品・記事・アカウントや管理画面での保存は、この環境では未確認です。ローカルプレビューのテストデータはストアへ登録した実データではありません。
